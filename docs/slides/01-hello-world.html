Welcome to the first step of the MCP Server course. By the end of this session you will have a running MCP server that an AI assistant can connect to and use.

What is MCP?

Model Context Protocol — an open standard for AI-tool integration

  • Open standard by Anthropic
  • Lets AI assistants connect to external tools and data
  • Language-agnostic protocol (we'll use Python)
  • Three primitives: Tools, Resources, Prompts
MCP is like a USB-C port for AI. Instead of every AI app building custom integrations, MCP gives us a standard protocol. Today we focus on Tools. Resources and Prompts come in step 02.

MCP Architecture


LLM Client (Claude, Cursor, etc.)
        ↕ MCP Protocol
MCP Server (your code)
        ↕
Your Data / APIs / Services

The MCP server is the bridge between the AI and your systems.

The client is whatever AI application the user is interacting with. Your MCP server sits in the middle, exposing capabilities that the LLM can discover and call. The server talks to your own backends, databases, APIs, etc.

What is FastMCP?

The Python SDK for building MCP servers

  • One decorator = one tool
  • Type annotations → automatic JSON schema
  • Multiple transport options (stdio, HTTP, SSE)
  • gofastmcp.com
FastMCP is the official high-level Python SDK. It handles all the protocol details so you can focus on writing plain Python functions. One decorator is all it takes to expose a function as an MCP tool.

Your First Server


from fastmcp import FastMCP

mcp = FastMCP(
    "HelloWorld",
    instructions="A simple demo MCP server. Use the echo tool "
                 "to echo messages and the add tool to add numbers.",
)

@mcp.tool
def echo(message: str) -> str:
    """Echo a message back to the caller."""
    return f"Echo: {message}"

if __name__ == "__main__":
    mcp.run(transport="http", host="0.0.0.0", port=8000)
This is a complete MCP server. We create a FastMCP instance with a name and instructions, define a tool with the decorator, and run it. The instructions field tells the LLM what this server does.

How Tools Work

  • @mcp.tool decorator exposes a function
  • Function name → tool name
  • Docstring → tool description
  • Type hints → input schema (automatic!)

@mcp.tool
def echo(message: str) -> str:
    """Echo a message back to the caller."""
    #     ^-- becomes the tool description
    return f"Echo: {message}"
FastMCP inspects your function at registration time. The function name becomes the tool name the LLM sees. The docstring becomes the description. And the type annotations are converted into a JSON schema that validates inputs.

Type Annotations Matter


@mcp.tool
def add(a: int, b: int) -> int:
    """Add two numbers together and return the result."""
    return a + b

@mcp.tool
def greet(name: str, greeting: str = "Hello") -> str:
    """Greet someone by name. Optionally customize the greeting."""
    return f"{greeting}, {name}! Welcome to MCP."
  • int types → JSON schema {"type": "integer"}
  • str types → JSON schema {"type": "string"}
  • Default values → parameter becomes optional
Notice how add takes two ints and greet has a default value for greeting. FastMCP converts these into a JSON schema automatically. The LLM uses that schema to know what arguments to pass. Default values make parameters optional in the schema.

Transport: HTTP Streamable


mcp.run(transport="http", host="0.0.0.0", port=8000)
  • Starts an HTTP endpoint at /mcp/
  • Recommended for network deployments
  • Supports multiple simultaneous clients
  • Alternative: "stdio" for local/desktop apps
HTTP streamable transport is the modern way to run MCP servers over the network. It exposes a single endpoint at /mcp/ that handles the protocol. Stdio transport is used when the client launches the server as a subprocess, which is common for desktop apps like Claude Desktop.

Running the Server


pip install -r requirements.txt
python server.py
# Server at http://localhost:8000/mcp/

Requirements:


fastmcp>=2.14.0
uvicorn>=0.34.0
Two dependencies: fastmcp itself and uvicorn as the ASGI server. Run server.py and you have a working MCP server. Let's see how to connect a client to it.

Connecting a Client

Add to your MCP client config (e.g. Claude Desktop, Cursor):


{
  "mcpServers": {
    "hello-world": {
      "url": "http://localhost:8000/mcp/"
    }
  }
}

The client discovers available tools automatically via the MCP protocol.

Most MCP clients use a JSON configuration file. You just point it at your server URL. The client will connect, discover the available tools, and make them available to the LLM. No manual registration needed.

Key Takeaways

  • FastMCP makes MCP servers trivial to build
  • Tools = functions the LLM can call
  • Type hints drive everything
  • HTTP transport for network access
