Natural Language to SQL

Ask questions in English, get SQL results

The NL2SQL Pipeline

"What did Chemistry spend on travel?"
    ↓ nl2sql.py
LLM generates SQL
    ↓ database.py
Validate SQL (safety check)
    ↓
Execute query → Results

Why DDL-Based Context?

  • LLMs are trained on millions of CREATE TABLE statements
  • DDL with inline comments produces much better SQL than prose descriptions
  • We send the full schema as DDL, not as "the table has columns..."
  • The LLM already knows how to read DDL — meet it where it is

Inline comments are CRITICAL — they tell the LLM what values look like

Critical Notes for the LLM

-- IMPORTANT NOTES FOR QUERY GENERATION:
-- 1. Fiscal year runs July 1 - June 30
--    (fiscal_period 1=July, 12=June)
-- 2. entry_type: 'actual' = real spending,
--    'budget' = planned, 'encumbrance' = committed
-- 3. For actual spending queries, filter:
--    entry_type = 'actual' AND amount > 0
-- 4. Use SUM(amount) for totals,
--    not COUNT(*)
-- 5. Department codes: COMPSCI, CHEM,
--    PHYS, MATH, ECE, BME, LAW, etc.

These prevent the most common SQL generation mistakes

def extract_sql_from_response(text: str) -> str:
    """Extract SQL from markdown code blocks."""
    if "```sql" in text:
        start = text.index("```sql") + 6
        end = text.index("```", start)
        return text[start:end].strip()
    if "```" in text:
        start = text.index("```") + 3

The ask Tool

@mcp.tool
async def ask(question: str, ctx: Context) -> str:
    await ctx.info(f"Understanding: {question}")
    sql = await nl_to_sql(question, config)
    await ctx.info(f"Generated SQL: {sql}")
    rows, total = await execute_query(
        config.database_path_resolved,
        sql, max_rows=config.max_rows)
    return json.dumps({"question": question,
        "sql": sql, "total_rows": total, "data": rows})

Chains: nl_to_sql → validate → execute → return results with generated SQL

Common NL2SQL Pitfalls

  • LLM uses COUNT(*) instead of SUM(amount) for totals
  • Forgets to filter entry_type = 'actual' for spending queries
  • Uses calendar year instead of fiscal year
  • Generates CTEs or window functions (SQLite limitations)

Solution: domain context in the prompt

The "IMPORTANT NOTES" section in SCHEMA_CONTEXT addresses each of these

Key Takeaways

  • DDL-based context > prose descriptions
  • Inline comments in DDL are critical
  • Always validate LLM-generated SQL before execution
  • Domain-specific notes prevent common mistakes
  • Prompt templates provide structured entry points
