Step 07

Mount a FastAPI App as an MCP Server

Same data as step 04. Same logic. Different framing.

The Punchline


from fastmcp import FastMCP

mcp = FastMCP.from_fastapi(app=app)
  • One line.
  • FastMCP reads your FastAPI app's OpenAPI spec.
  • Every route becomes an MCP tool — automatically.

📚 gofastmcp.com/integrations/fastapi

Why This Matters

  • You probably already have a FastAPI app. That's thousands of existing deployments.
  • Rewriting it as MCP tools means duplicated code, drift, two test suites.
  • from_fastapi lets one codebase serve both REST clients (curl, dashboards, browsers) and MCP clients (Claude Desktop, Cursor, VS Code).
  • Under the hood: FastMCP's OpenAPI integration, which also works for any OpenAPI spec — not just FastAPI.

📚 OpenAPI integration

What This Branch Ships

  • Same data layer as step 04: config.py, database.py, data/university_gl.db
  • Same domain content: fund types, chart of accounts, departments
  • Rewritten server.py: FastAPI first, from_fastapi wrap, combined ASGI app
  • One uvicorn process serves both:
    • REST at /query, /schema/..., /domain/...
    • MCP at /mcp

Three Pieces of server.py

  1. A plain FastAPI app. Nothing MCP-specific. Deploy as REST if you want.
  2. FastMCP.from_fastapi(app=app). One line. OpenAPI → MCP tools.
  3. A combined ASGI app that splats both route sets: 
    
combined = FastAPI(
    lifespan=mcp_app.lifespan,
    routes=[*mcp_app.routes, *app.routes],
)

Piece 1: The FastAPI App


from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI(title="University GL API", version="1.0.0")

class QueryRequest(BaseModel):
    sql: str = Field(..., description="A read-only SELECT or WITH query.")

@app.post("/query", response_model=QueryResponse, operation_id="query_sql")
async def query_sql(request: QueryRequest) -> QueryResponse:
    """Execute a read-only SELECT query."""
    rows, total = await execute_query(
        config.database_path_resolved, request.sql, max_rows=config.max_rows
    )
    return QueryResponse(total_rows=total, returned_rows=len(rows),
                        truncated=total > config.max_rows, data=rows)

Totally ordinary FastAPI. Pydantic models, type hints, docstring, HTTPException.

Set operation_id on Every Route


# Good — explicit, readable MCP tool name
@app.get("/database/info", operation_id="get_database_info")
def get_database_info() -> list[dict]: ...

# Bad — auto-generated tool name: list_tables_schema_tables_get
@app.get("/schema/tables")
def list_tables() -> list[dict]: ...
  • FastMCP uses operation_id verbatim as the tool name
  • Without it, names are constructed from function_name + path + method
  • LLMs reason better with clean tool names

📚 FastAPI integration: Key Considerations

Piece 2: Wrap It


from fastmcp import FastMCP

mcp = FastMCP.from_fastapi(
    app=app,
    name="FinancialData (via FastAPI)",
)

Piece 3: Serve Both from One Process


mcp_app = mcp.http_app(path="/mcp")

combined_app = FastAPI(
    title="University GL — REST + MCP",
    lifespan=mcp_app.lifespan,          # ← critical
    routes=[*mcp_app.routes, *app.routes],
)
  • mcp.http_app(path="/mcp") returns a mountable ASGI app
  • Splat both route sets into a new FastAPI
  • Borrow the MCP app's lifespan — required for session manager init

When To Use from_fastapi

✅ Good fit

  • You already have a FastAPI app
  • You're prototyping / bootstrapping
  • Your REST shape is close to the MCP shape you'd want
  • You want Swagger UI + MCP from the same code

⚠️ Not a great fit

  • Designing the MCP surface from scratch
  • Lots of path params / complex query params
  • Auth not already solved in the FastAPI app
  • Production-quality LLM interfaces

The FastMCP team recommends hand-crafted tools for production. See "Stop Converting Your REST APIs to MCP".

Key Takeaways

  • FastMCP.from_fastapi(app) turns any FastAPI app into an MCP server in one line
  • Under the hood it's the OpenAPI integration — any OpenAPI spec works, not just FastAPI
  • Always set operation_id= on your FastAPI routes — that's the MCP tool name
  • Combine both surfaces with the routes-splat pattern; borrow the MCP lifespan
  • Great for prototyping; purpose-built MCP tools still win for production LLM UX
