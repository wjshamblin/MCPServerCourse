OIDC in 60 Seconds

  • OpenID Connect = identity layer on top of OAuth 2.0
  • Provider advertises everything at a discovery URL: .well-known/openid-configuration
  • Standard endpoints: authorize, token, userinfo, introspect
  • Duke's discovery:
    https://oauth.oit.duke.edu/oidc/.well-known/openid-configuration

Register a Duke OAuth App

  • Register at authentication.oit.duke.edu/manager/oauth/register
  • Prerequisite: ServiceNow support group
  • Redirect URI: http://localhost:8000/callback
    (must match SERVER_BASE_URL + /callback)
  • Scopes: openid, email, profile, offline_access
  • Enable Introspection: Yes — required below

The Whole Server — Setup


import os, httpx, logging
from dotenv import load_dotenv
from fastmcp import FastMCP
from fastmcp.server.auth import AccessToken, TokenVerifier
from fastmcp.server.auth.oidc_proxy import OIDCProxy
from fastmcp.server.dependencies import get_access_token

load_dotenv()

OIDC_WELL_KNOWN_URL = os.environ["OIDC_WELL_KNOWN_URL"]
OIDC_CLIENT_ID      = os.environ["OIDC_CLIENT_ID"]
OIDC_CLIENT_SECRET  = os.environ["OIDC_CLIENT_SECRET"]
OIDC_SCOPES         = os.environ.get("OIDC_SCOPES",
                        "openid email profile offline_access")
SERVER_BASE_URL     = os.environ.get("SERVER_BASE_URL",
                        "http://localhost:8000")

Env-driven. No pydantic-settings, no Settings class.

The Introspection Problem

  • Duke OIDC tokens are opaque — not self-describing JWTs
  • The stock JWTVerifier can't read scopes out of them
  • RFC 7662 introspection: POST the token back to Duke's /introspect and trust the response
  • Same pattern applies to any OIDC provider that issues opaque tokens

IntrospectionTokenVerifier


class IntrospectionTokenVerifier(TokenVerifier):
    def __init__(self, introspection_endpoint, client_id, client_secret):
        self.introspection_endpoint = introspection_endpoint
        self.client_id = client_id
        self.client_secret = client_secret
        self.required_scopes = OIDC_SCOPES.split()

    async def verify_token(self, token: str) -> AccessToken | None:
        async with httpx.AsyncClient() as c:
            resp = await c.post(self.introspection_endpoint,
                data={"token": token},
                auth=(self.client_id, self.client_secret))
        if resp.status_code != 200 or not resp.json().get("active"):
            return None
        data = resp.json()
        return AccessToken(
            token=token,
            client_id=data.get("client_id", "unknown"),
            scopes=(data.get("scope") or "").split(),
            claims={k: data.get(k) for k in (
                "sub","email","name","dukeNetID","dukeUniqueID",
                "dukePrimaryAffiliation") if data.get(k)},
        )

Wiring the OIDCProxy


_metadata = httpx.get(OIDC_WELL_KNOWN_URL).json()

auth = OIDCProxy(
    config_url=OIDC_WELL_KNOWN_URL,
    client_id=OIDC_CLIENT_ID,
    client_secret=OIDC_CLIENT_SECRET,
    base_url=SERVER_BASE_URL,
    token_verifier=IntrospectionTokenVerifier(
        introspection_endpoint=_metadata["introspection_endpoint"],
        client_id=OIDC_CLIENT_ID,
        client_secret=OIDC_CLIENT_SECRET,
    ),
    extra_authorize_params={"scope": OIDC_SCOPES},
)

mcp = FastMCP("DukeOIDCDemo", auth=auth)

The auth=auth on the top-level FastMCP is what publishes the well-known endpoints.

Tools & Resources


@mcp.tool
def hello(name: str = "world") -> str:
    return f"hello, {name}!"

@mcp.tool
def whoami() -> dict:
    tok = get_access_token()
    if tok is None:
        return {"error": "no access token in context"}
    return {
        "client_id": tok.client_id,
        "scopes": tok.scopes,
        "claims": tok.claims,
    }

@mcp.resource("user://me")
def me() -> dict:
    return whoami()

hello is the "your auth is working" smoke test. whoami is the meaningful identity check.

Endpoints You Get For Free

If any well-known returns 404, auth=auth isn't on the instance you're running.

Key Takeaways

  • Duke OIDC uses OIDCProxy, not OAuthProxy
  • Discovery URL auto-configures all endpoints
  • Opaque tokens ⇒ introspection, not JWT validation
  • auth must be on the top-level FastMCP — it's what publishes the well-known endpoints
  • Four deps, one file, one new idea
