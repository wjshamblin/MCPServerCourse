Step 07

Azure OAuth Authentication

Securing your MCP server with Azure AD

Why Authenticate?

  • Our financial server has sensitive data
  • Without auth, anyone on the network can query it
  • We need:
    • Identity — who is this?
    • Authorization — are they allowed?
  • Azure AD / Entra ID is the enterprise standard

OAuth 2.0 in 60 Seconds


User ──"Login with Azure"──> Azure AD login page
Azure AD ──auth code──> Your server
Your server ──code + secret──> Azure AD
Azure AD ──access token──> Your server
Your server ──JWT──> MCP client

What is a Confidential Client?

  • Has a client secret stored securely on the server
  • Secret proves the server's identity to Azure AD
  • Appropriate when: server is in a trusted environment
  • The server authenticates itself, not just the user


vs. Public Client (Step 09): no secret, used for desktop/mobile apps

Register the Application

  1. Azure Portal → Azure Active Directory → App registrations → New
  2. Name: "MCP Financial Server"
  3. Single tenant (your org only)
  4. Redirect URI: http://localhost:8000/mcp/oauth/callback
  5. Copy Client ID and Tenant ID

Create Client Secret

  1. Certificates & secrets → New client secret
  2. Add a description, choose expiry
  3. Copy the VALUE immediately


Warning: The secret value is shown only once!


This goes in your .env file:


AZURE_CLIENT_SECRET=your-secret-value-here

Expose an API

  1. Expose an API → Set Application ID URI (accept default)
  2. Add a scope: access_as_user
  3. Who can consent: Admins and users


This creates the scope:


api://<client-id>/access_as_user

This scope is what MCP clients request when authenticating

Duke-Specific: App Approval

  • Duke's Azure tenant requires admin approval for new apps
  • Email help@oit.duke.edu (group: Cloud Services)
  • Describe your app's purpose and scope
  • App won't work until approved by tenant administrators


Plan ahead — approval can take several business days

FastMCP Auth Setup


from fastmcp.server.auth import OAuthProxy
from fastmcp.server.auth.providers.jwt import JWTVerifier
base = f"https://login.microsoftonline.com/{tenant}"
token_verifier = JWTVerifier(
    jwks_uri=f"{base}/discovery/v2.0/keys",
    issuer=f"{base}/v2.0", audience=config.azure_client_id)
auth = OAuthProxy(
    upstream_authorization_endpoint=f"{base}/oauth2/v2.0/authorize",
    upstream_token_endpoint=f"{base}/oauth2/v2.0/token",
    upstream_client_id=config.azure_client_id,
    upstream_client_secret=config.azure_client_secret,
    upstream_scopes=[config.full_mcp_scope],
    token_verifier=token_verifier)
mcp = FastMCP("Server", auth=auth)

Why OAuthProxy?

  • MCP clients use Dynamic Client Registration (DCR)
  • Azure AD doesn't support DCR natively
  • OAuthProxy bridges the gap:


MCP Client ──DCR──> OAuthProxy ──OAuth 2.0──> Azure AD

  • Presents a DCR-compatible interface to MCP clients
  • Translates to standard OAuth 2.0 against Azure AD
  • Also mints its own JWTs and encrypts stored tokens

Authenticated User


from fastmcp.server.dependencies import get_access_token

@mcp.tool
async def get_authenticated_user() -> str:
    token = get_access_token()
    if not token:
        return json.dumps({"error": "Not authenticated"})
    claims = token.claims or {}
    return json.dumps({
        "email": claims.get("preferred_username"),
        "name": claims.get("name"),
    })

get_access_token() works in any tool — no ctx parameter needed

Graceful Degradation


auth = None
if config.auth_enabled:  # AZURE_CLIENT_ID is set
    token_verifier = JWTVerifier(...)
    auth = OAuthProxy(...)

mcp = FastMCP("Server", auth=auth)

  • Auth is disabled when Azure vars are empty
  • Server still works without auth for development
  • Production: always set the Azure vars

# config.py
@property
def auth_enabled(self) -> bool:
    return bool(self.azure_client_id and self.azure_tenant_id)

Key Takeaways

  • OAuthProxy bridges Azure AD with MCP's DCR protocol
  • JWTVerifier validates tokens using Azure's JWKS endpoint
  • get_access_token() gets the user's token in any tool
  • Auth gracefully degrades when Azure vars aren't set
  • Duke apps need admin approval via help@oit.duke.edu
