Step 10

Directory Server with On-Behalf-Of

Reaching Microsoft Graph as the calling user

Why This Branch Grows

  • Steps 07 – 09 were intentionally tiny (one file, one idea)
  • Step 10 keeps the same auth shape but now does something substantive: call Microsoft Graph on the user's behalf
  • That needs real code, so server.py pulls in four supporting modules
  • All composition-with-financial-server framing is gone — server.py is the directory server

The Problem OBO Solves

The user's MCP token is scoped for our API:

aud = api://<our client id>/access_as_user

Graph won't accept that token — it wants its own audience:

aud = https://graph.microsoft.com
  • App-only creds would work, but then every user gets the union of Graph permissions our app was granted
  • OBO exchanges the user's MCP token for a Graph token with the user's identity preserved

OBO Flow

User → MCP client → Our server
                      │
                      │ POST /token (jwt-bearer grant)
                      │   assertion = user's MCP token
                      │   scope     = Graph scopes
                      │   client_id + client_secret (confidential!)
                      ▼
                   Azure AD
                      │
                      │ New access_token (aud=graph.microsoft.com)
                      │ preserves oid/upn of user
                      ▼
                   Our server ──────── GET /users?...  ──────▶ Graph
                                                               │
                                       ◀────── user results ───┘

Grant type: urn:ietf:params:oauth:grant-type:jwt-bearer + requested_token_use=on_behalf_of.

Why Confidential Again?

  • OBO requires the downstream call to /token be authenticated
  • Public clients can't do that — they have no secret
  • So step 10 backs off to a confidential client (secret in the server's env)
  • Step 09's security add-ons (allowlist, audit) still apply in principle; this branch keeps focus on OBO, so they're not re-added here

OBOTokenExchange


class OBOTokenExchange:
    async def exchange(self, user_token: str) -> str:
        # Return cached exchange if still fresh
        cached = self._cache.get(user_token)
        if cached and cached.expires_at > time.time():
            return cached.access_token

        data = {
          "client_id":            self.client_id,
          "client_secret":        self.client_secret,
          "assertion":            user_token,
          "scope":                self.scopes,
          "requested_token_use":  "on_behalf_of",
          "grant_type":           "urn:ietf:params:oauth:grant-type:jwt-bearer",
        }
        r = await self._http.post(self.token_endpoint, data=data)
        if r.status_code != 200:
            raise OBOExchangeError(r.text)
        body = r.json()
        self._cache[user_token] = _CacheEntry(
            access_token=body["access_token"],
            expires_at=time.time() + min(body["expires_in"], self.ttl))
        return body["access_token"]

TTL cache avoids hammering Azure on every tool call.

DirectoryService


class DirectoryService:
    async def find_user(self, user_token: str, query: str):
        graph_token = await self.obo.exchange(user_token)
        return await self.graph.search_users(graph_token, query)

    async def get_user_groups(self, user_token: str, user_id: str):
        graph_token = await self.obo.exchange(user_token)
        return await self.graph.list_member_of(graph_token, user_id)

Tools stay thin; OBO + Graph never leak into the MCP surface.

MCP Tools & Resource


@mcp.tool
async def find_user(query: str) -> str:
    tok = get_access_token()
    if not tok: return json.dumps({"error": "Not authenticated"})
    try:
        results = await directory.find_user(tok.token, query)
    except OBOExchangeError as e:
        return json.dumps({"error": f"OBO exchange failed: {e}"})
    users = [UserResult.from_graph(r).model_dump() for r in results]
    return json.dumps({"query": query, "count": len(users),
                       "results": users}, indent=2)

Key Takeaways

  • OBO lets a server call downstream APIs as the user, not as the app
  • Requires a confidential client — the secret is part of the exchange
  • The tool surface stays tiny; the work lives in OBOTokenExchange + GraphClient + DirectoryService
  • Cache exchanged tokens — don't re-exchange on every call
  • Preserves audit, least-privilege, and user identity across the network hop
