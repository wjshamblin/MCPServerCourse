The Config Pattern

from pydantic_settings import BaseSettings, SettingsConfigDict
from pydantic import Field

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env")

    database_path: str = Field(
        default="data/university_gl.db"
    )
    max_rows: int = Field(default=2000)
    warning_rows: int = Field(default=100)
    log_level: str = Field(default="INFO")
  • Environment variables override defaults
  • .env file for local development
  • Type validation built in

SQL Safety: The Problem

  • LLMs generate SQL. LLMs hallucinate.
  • An LLM could generate: DROP TABLE gl_transactions
  • Even without malice, bad SQL can crash the server
  • We need a safety layer

SQL Safety: The Solution

DANGEROUS_PATTERNS = [
    re.compile(r"\b(DROP|DELETE|INSERT|UPDATE|ALTER|"
               r"CREATE|TRUNCATE|REPLACE)\b", re.IGNORECASE),
    re.compile(r"\b(ATTACH|DETACH)\b", re.IGNORECASE),
    re.compile(r"--"),  re.compile(r"/\*"),  # comments
]

def validate_sql(sql: str) -> None:
    stripped = sql.strip().rstrip(";")
    if not stripped.upper().startswith("SELECT"):
        raise SQLValidationError("Only SELECT allowed.")
    for p in DANGEROUS_PATTERNS:
        if p.search(stripped): raise SQLValidationError(...)

Tool: query_sql

@mcp.tool
async def query_sql(sql: str, ctx: Context) -> str:
    try:
        rows, total = await execute_query(
            config.database_path_resolved,
            sql, max_rows=config.max_rows)
    except SQLValidationError as e:
        return f"Query validation error: {e}"
    if total > config.warning_rows:
        await ctx.warning(f"Query returned {total:,} rows")
    return json.dumps({"total_rows": total,
        "returned_rows": len(rows), "data": rows})

Tool: get_database_info

@mcp.tool
async def get_database_info(ctx: Context) -> str:
    """Get a summary of all tables, their columns,
    and row counts. Call this first to understand the
    database structure before writing queries."""
    tables = await get_table_info(
        config.database_path_resolved
    )
    await ctx.info(f"Found {len(tables)} tables")
    return json.dumps(tables, indent=2)

Returns table names, column details, row counts — the LLM calls this first to understand the schema

Schema Resources

@mcp.resource("schema://tables",
              mime_type="application/json")
async def list_tables() -> str:
    """List all tables with row counts."""

@mcp.resource("schema://{table_name}/columns",
              mime_type="application/json")
async def table_columns(table_name: str) -> str:
    """Column details for any table."""
  • schema://tables → list of tables with row counts
  • schema://{table_name}/columns → column details for any table
  • Resources give the LLM structural knowledge before querying

Domain Resources — the secret sauce

  • domain://funds → explains fund accounting
  • domain://accounts → chart of accounts reference
  • domain://departments → department listing by school

Without these, the LLM has NO IDEA what fund codes mean

Why Domain Resources Matter

Without

LLM sees: fund_code = '20'

→ meaningless number

With domain://funds

"Fund 20 = Restricted Grants (NSF, NIH)"

→ understands the data

Domain resources bridge the gap between schema and meaning

This is what makes NL2SQL actually work

Key Takeaways

  • Pydantic Settings for configuration
