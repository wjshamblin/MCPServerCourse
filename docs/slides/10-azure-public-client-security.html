Step 10

Public Client + PKCE + Security Add-Ons

What to do when the server can't hold a secret

What Changes vs Step 09

  • Drop upstream_client_secret — this is a public client
  • Azure validates request integrity with PKCE instead of a secret
  • FastMCP needs a local jwt_signing_key to mint tokens for downstream MCP clients
  • Add two production concerns that naturally live here:
    • User allowlist on privileged tools
    • Tamper-detected audit log (SHA-256 hash chain)

PKCE in One Slide

1. Client picks a random code_verifier
2. Client sends SHA256(code_verifier) as code_challenge on /authorize
3. Azure stashes the challenge alongside the issued auth code
4. Client sends the raw code_verifier on /token
5. Azure checks SHA256(code_verifier) == stored challenge
   → only the original caller can redeem the code

FastMCP's OAuthProxy does steps 2+4 automatically (forward_pkce=True by default).

Register as a Public Client

  1. Portal → App registrations → New registration
  2. Platform: Mobile and desktop applications
  3. Redirect URI: http://localhost:8000/callback
  4. Authentication → turn on "Allow public client flows"
  5. Expose an API → scope access_as_user
  6. Do not create a client secret

Why jwt_signing_key?

  • In step 09 the MCP-facing token was essentially the Azure JWT (secret-backed trust)
  • Public clients can't issue that trust end-to-end, so FastMCP mints its own short-lived JWT for the MCP client
  • That JWT needs a symmetric signing key — that's jwt_signing_key
  • Without it, OAuthProxy raises at startup: "jwt_signing_key is required when upstream_client_secret is not provided"

Allowlist Pattern


ALLOWED_USERS = [e.strip().lower()
                 for e in os.environ.get("ALLOWED_USERS", "").split(",")
                 if e.strip()]

def caller_email() -> str:
    tok = get_access_token()
    if tok is None: return ""
    c = tok.claims
    return (c.get("upn") or c.get("preferred_username")
            or c.get("email") or "").lower()

def check_user_allowed(email: str) -> bool:
    # Empty allowlist = allow any authenticated user
    return not ALLOWED_USERS or email in ALLOWED_USERS

Authentication answers "who is this?"; the allowlist answers "are they allowed to do this?"

A Privileged Tool


@mcp.tool
def privileged_action(message: str) -> dict:
    email = caller_email()
    if not check_user_allowed(email):
        audit.log(email or "<unknown>", "DENIED",
                  f"privileged_action: {message[:200]}")
        return {"error": "not authorized", "user": email}

    audit.log(email, "ALLOWED",
              f"privileged_action: {message[:200]}")
    return {"ok": True, "user": email, "echoed": message}
  • Extract identity from the token
  • Gate on the allowlist
  • Audit both outcomes — denials matter too

Tamper-Detected Audit Log

  • Every entry = JSON line with timestamp, user, action, details, prev_hash, hash
  • hash = SHA256(prev_hash || json_of(this_entry_without_hash))
  • Changing or deleting any past line breaks every subsequent hash
  • Exposed to clients via audit://verify:

@mcp.resource("audit://verify")
def verify_audit_chain() -> dict:
    valid, count = audit.verify_chain()
    return {"valid": valid, "entries": count}

This is integrity, not confidentiality. A sufficiently motivated attacker with write access could rewrite the whole chain — in production, ship entries to append-only storage.

Key Takeaways

  • Public client = no secret; PKCE proves identity end-to-end
  • jwt_signing_key is required because FastMCP mints its own token
  • Authentication and authorization are different questions — allowlist solves the second
  • Audit both allowed and denied calls; a hash chain makes silent tampering detectable
  • Still one file, still minimal — auth lessons end here
