When to Use Public Clients

  • Can't securely store a client secret (desktop apps, CLI tools)
  • Want to eliminate secret rotation overhead
  • PKCE provides sufficient security
  • Actually MORE secure than confidential in some cases — no secret to leak!

PKCE: Proof Key for Code Exchange

1. Client generates random code_verifier
2. Client computes code_challenge = SHA256(code_verifier)
3. Auth request includes code_challenge
4. Token exchange includes code_verifier
5. Server verifies: SHA256(verifier) == challenge

Prevents authorization code interception — attacker needs the verifier.

FastMCP handles this automatically.

Authorization after authentication

def check_user_allowed(email: str) -> bool:
    allowed = config.allowed_users_list
    if not allowed:
        return True  # empty = allow all
    return email.lower() in allowed

Authentication = who are you?
Authorization = are you allowed?

Audit Logging: Why?

  • Compliance requirements (FERPA, SOX, HIPAA)
  • Forensics: who queried what, when?
  • Tamper detection: were logs modified?
  • We need: append-only, verifiable, timestamped

Hash Chain Integrity

Entry 1: {data, hash: SHA256(data), previous_hash: "GENESIS"}
Entry 2: {data, hash: SHA256(data), previous_hash: entry1.hash}
Entry 3: {data, hash: SHA256(data), previous_hash: entry2.hash}

If ANY entry is modified or deleted, the chain breaks.

verify_chain() detects tampering.

Audit Logger

class AuditLogger:
    def log(self, user_email, action, detail="", result_count=0):

            "timestamp": datetime.now(UTC).isoformat(),
            "user": user_email,
            "action": action,    # QUERY, DENIED, NL_QUERY
